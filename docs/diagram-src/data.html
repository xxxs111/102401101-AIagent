图 C　数据模型与状态流转

一条信息（item）的字段设计，以及「进行中 ⇄ 已完成」的双向流转规则

① 数据模型 item

字段取值说明
id1, 2, 3…自增主键，generateId() 取当前最大值 + 1
typelost / found寻物 / 招领，决定表单文案与配色（玫瑰红 / 青绿）
name · category校园卡 / 校园卡名称 ≤ 30 字；分类为 9 项白名单
time · place2026-10-06 / 三区田径场看台日期不得晚于今天；地点 ≤ 50 字
desc · image蓝色卡套… / http(s) 链接描述 ≤ 200 字；图片用链接方式，可留空
contactName · contact李同学 / 13800001234联系方式支持手机号 / QQ / 微信 / 邮箱
statusactive / done进行中 / 已完成，只允许这两种取值
publisherKeyowner_xxx本机发布者标识，决定是否显示管理按钮
views · createdAt · updatedAt26 / 时间戳浏览数与时间戳，用于排序与"多久之前"

② 状态流转

active　进行中 寻物 → 「寻找中」
招领 → 「待认领」
列表正常展示 · 显示联系入口
updateStatus(id,'done')
➜
updateStatus(id,'active')
◀
非法状态值一律拒绝
done　已完成 寻物 → 「已找到」
招领 → 「已归还」
列表置灰后置 · 隐藏联系入口
文案统一由一处输出 Utils.statusOf(item) 把 status × type 映射成四种文案， 界面层只认这个函数，避免"寻找中 / 已找到 / 待认领 / 已归还"散落在十几个模板里。
排序规则 进行中在前，同状态按发布时间倒序。已完成的信息自动后置， 不会被新的已完结信息淹没有效信息。
权限规则 详情页与「我的发布」的管理按钮只在 publisherKey 与本机标识一致时出现；地址栏直接进 #/edit/:id 也会被拦下。
被测试锁住的边界：不存在 id 返回 null 且数据不变 · 非法状态值拒绝执行 · 恢复操作可逆 · 更新状态会刷新 updatedAt
