## 四、测试报告模板

> 直接复制到博客里，把【待填】换掉。

### 4.1 测试工具与学习过程

- **工具**：原生 JavaScript 手写断言，零框架、零依赖、离线可运行。
- **为什么不用现成框架**：本项目要求"Chrome 直接打开 html 就能运行"，引入 QUnit 需要额外下载文件、引入 Jest/Mocha 需要 Node 环境，都会抬高助教的验收门槛；而我们要测的都是纯函数，5 个断言方法（`ok / equal / notEqual / deepEqual / throws`）已经够用。
- **学习过程**：先看邹欣老师《单元测试之道》相关博客理解"自动化、每天可运行"的思想，再对照本项目逻辑层（`utils.js` / `store.js` / `view.js` 不依赖 DOM）设计用例。
- **一份简易教程（三步上手）**：
  1. 打开 `index.html`，按 F12 进 Console；
  2. 把 `test/unit-test.js` 全部内容粘贴进 Console，回车（浏览器若提示禁止粘贴，先输入 `allow pasting` 解锁）；
  3. 输入 `runTest()` 回车，Console 里绿色 ✔ 为通过，红色 ✘ 会带上失败原因。
  更省事的方式：直接打开 `test/test.html`，加载即自动运行并把结果显示在页面上。

### 4.2 测试范围与用例设计

- **规模**：61 个用例，覆盖 6 个模块。
- **覆盖的函数**：
  - 工具层 `Utils`：`escapeHtml`、`toDateStr`、`parseDate`、`isFutureDate`、`friendlyDate`、`timeAgo`、`statusOf`、`typeLabel`、`categoryIcon`、`uid`（10 例）
  - 校验 `Store.isValidPublishData` / `isValidContact`（11 例）
  - 数据层 `Store`：`loadItems`、`saveItems`、`generateId`、`getItem`、`createItem`、`updateItem`、`deleteItem`、`incrementViews`（19 例）
  - 状态流转与搜索统计：`updateStatus`、`searchItems`、`sortItems`、`countByType`、`getMyItems`、`isMine`（11 例）
  - 演示数据 `seedIfEmpty`、`clearAll`（5 例）
- **构造测试数据**：每个用例前 `resetStorage()` 清库保证隔离；用 `fixtures()` 固定写入 4 条数据（含寻物/招领、进行中/已完成、不同地点与联系方式格式），保证用例可重复、可预期；日期用"相对今天偏移 N 天"生成，避免写死日期导致用例过期。
- **覆盖的场景**：
  - 正常：合法数据发布成功、状态流转、关键词命中；
  - 边界：名称正好 30 字 / 地点正好 50 字 / 描述正好 200 字 / 日期正好今天 / 关键词带首尾空格 / 大小写不一致 / 微信与 QQ 的位数边界；
  - 异常：空表单、纯空格、超长、未来日期、非法联系方式、不存在的 id、非法状态值、存储内容损坏、中文与 emoji 往返。

### 4.3 测试运行结果

- 用例总数 **61**，通过 **61**，失败 **0**。
- 运行耗时约 **8–15 ms**。
- 截图：`docs/screenshots/10-unit-test-all-pass.png`（测试页全览）、`docs/screenshots/09-about-tests.png`（应用内一键运行）。

### 4.4 测试抓出的问题（真实的两条）

| 问题 | 现象 | 原因 | 修复 |
| --- | --- | --- | --- |
| 联系方式校验放行了少一位的手机号 | 断言 `1380000123` 应非法却失败 | 该串满足"5-12 位纯数字"，被当成合法 QQ | 纯数字串先按手机号规则判定，`1[3-9]` 开头但位数不对直接判非法；QQ 收紧为 5-11 位。已加永久回归用例 |
| 非法日期被静默接受 | 断言 `2026-13-01` 应返回 `null` 却返回了 2027-01-01 | `new Date()` 对越界月份不报错而是溢出 | `parseDate` 自行校验月份/日期范围并检查溢出，非法返回 `null` |

另外还发现并修复了一条数据安全的隐患：演示数据播种最初只检查"是否播种过"，用户清掉标记但保留自己数据时会被整体覆盖；现在加了"已有数据一律不播种"守卫，并留了对应的回归用例。

### 4.5 测试评估

- **覆盖程度**：逻辑层（校验、存储、搜索、状态流转、转义、模板输出）的全部核心函数与主要异常分支都有用例，能满足本程序的测试要求。
- **未覆盖**：`app.js` 的视图渲染、事件绑定、剪贴板交互没有自动化覆盖，这部分用浏览器实测补足（见第三节走查清单与截图）。
- **改进方向**：若后续要做端到端自动化，可引入 Playwright 覆盖界面层。
